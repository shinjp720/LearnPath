# 正規表現 <a id="top" data-name="TOP"></a>

正規表現とは、文字列のパターンを表現するための記法で、文字列の検索・抽出、置換、検証 (バリデーション) などを行うために使用する。<br>
多くの言語や環境でサポートされている。

| 使い道 | 例 |
| --- | --- |
| 検索 | ログから、`ERROR` を含む行を探す |
| 抽出 | 文章から、日付や、電話番号を取り出す |
| 置換 | 連続する空白を、1つにまとめる |
| 検証 | 入力された値が、郵便番号の形式かを確認する |
| 分割 | `,` や空白など、複数の区切りで、文字列を分ける |

<pre><code class="caution">正規表現の書き方は、言語やツール (方言) によって、少しずつ違う。
このドキュメントでは、ほとんどの環境で共通する書き方を中心に説明し、違いがあるものは、「言語ごとの違い」の章にまとめている。</code></pre>

---

## 基本の考え方 <a id="concept" data-name="基本の考え方"></a>

正規表現は、次の要素の組み合わせ。

```text
[文字] + [量] + [条件]
```

| 要素 | 役割 | 例 |
| --- | --- | --- |
| 文字 | どんな文字か | `a`、`\d`、`[a-z]` |
| 量 | 何回繰り返すか | `+`、`{3}`、`?` |
| 条件 | どこにあるか、何が前後にあるか | `^`、`$`、`\b`、`(?=...)` |

### 読み方の例

```regex
^\d{3}-\d{4}$
```

| 部分 | 意味 |
| --- | --- |
| `^` | 文字列の先頭 |
| `\d` | 数字1文字 |
| `{3}` | 直前の要素を、3回繰り返す |
| `-` | ハイフンそのもの |
| `\d{4}` | 数字4文字 |
| `$` | 文字列の末尾 |

「先頭から、数字3文字、ハイフン、数字4文字で、そこで終わり」という意味になる (郵便番号の形式)。

### 試せるツール

| ツール | 内容 |
| --- | --- |
| regex101 (regex101.com) | 正規表現を入力して、一致の結果と、各部分の説明を確認できる。言語 (方言) も選べる |
| エディタの検索 | VS Code などの、正規表現のオプション (`.*` のボタン) を有効にして、検索や置換に使える |
| `grep -E` / `sed -E` | コマンドラインで、ファイルを検索・置換する |
| 各言語の REPL | 実際に使う言語で、動作を確認する |

<pre><code class="tips">正規表現は、書いてすぐに、一致する例と、一致しない例の、両方で試す。
一致する例だけで確認すると、「何にでもマッチする」ような、緩すぎるパターンに気付けない。</code></pre>

## 文字 <a id="literal" data-name="文字"></a>

| 表現 | 意味 | 一致する例 |
| --- | --- | --- |
| `a` | 文字 a | `a` |
| `abc` | 文字列 "abc" | `abc` (`abd` には、一致しない) |
| <code>cat&#124;dog</code> | "cat" または "dog" | `cat`、`dog` |
| `.` | 改行以外の任意の1文字 | `a`、`1`、`あ`、`-` |

```regex
a.c
```

```text
abc    ← 一致
a1c    ← 一致
ac     ← 一致しない (a と c の間に、1文字が必要)
```

### エスケープ (特殊文字を、文字として扱う)

正規表現では、次の文字が、特別な意味を持つ (メタ文字)。

```text
\  ^  $  .  |  ?  *  +  (  )  [  ]  {  }
```

これらの文字を、そのままの文字として検索したい場合は、前に `\` (バックスラッシュ) を付ける。

| 表現 | 意味 |
| --- | --- |
| `\.` | `.` (ピリオド) |
| `\+` | `+` |
| `\*` | `*` |
| `\?` | `?` |
| `\(` `\)` | `(` `)` |
| `\[` `\]` | `[` `]` |
| `\{` `\}` | `{` `}` |
| `\\` | `\` |
| `\/` | `/` (JavaScript の `/.../` の中では、必要) |

改行やタブなどの、見えない文字も、`\` で表す。

| 表現 | 意味 |
| --- | --- |
| `\n` | 改行 (LF) |
| `\r` | 復帰 (CR) |
| `\t` | タブ |

<pre><code class="caution">ピリオド (.) は、「任意の1文字」を意味するため、「.」という文字を探すときは、\. と書く。
たとえば、拡張子 .txt を探すときに、.txt と書くと、「atxt」のような文字列にも、一致してしまう。</code></pre>

## 文字クラス <a id="char-class" data-name="文字クラス"></a>

特定の文字が一致すべき文字の集合を定義する構文。<br>
`[ ]` で囲むか、ショートハンド (`\d` など) で、文字列から抽出する。`[ ]` の中の文字のうち、**どれか1文字**に、一致する。

| 表現 | 意味 | 一致する例 |
| --- | --- | --- |
| `[abc]` | aかbかc1文字 | `a`、`b` |
| `[a-z]` | 小文字アルファベット1文字 | `m` |
| `[A-Z]` | 大文字アルファベット1文字 | `M` |
| `[0-9]` | 数字1文字 | `7` |
| `[a-zA-Z0-9]` | 英数字1文字 (範囲は、並べて書ける) | `x`、`X`、`5` |
| `[^abc]` | a, b, c以外の1文字 | `d`、`1` |
| `[^0-9]` | 数字以外の1文字 | `a`、`-` |

### 文字クラスの中の特殊文字

`[ ]` の中では、特殊文字の意味が、外とは変わる。

| 文字 | `[ ]` の中での扱い |
| --- | --- |
| `.`、`*`、`+`、`?`、`(`、`)`、`$` | 特殊な意味を持たず、そのままの文字 (`[.]` は、ピリオドだけに一致する) |
| `^` | **先頭に置いたときだけ**、否定の意味になる (`[^a]`)。それ以外は、そのままの文字 |
| `-` | 文字の間に置くと、範囲の意味になる (`[a-z]`)。先頭か末尾に置くと、ハイフンそのもの (`[-a]`、`[a-]`) |
| `]` | クラスの終わり。文字として使うなら `\]` |
| `\` | エスケープの開始。文字として使うなら `\\` |

```regex
[.+*]      ← . か + か * のどれか1文字
[^.]       ← ピリオド以外
[a-z-]     ← 小文字か、ハイフン
```

### ショートハンド

よく使われる文字クラスを短く表現するための省略記法

| ショートハンド | 文字クラスでの表現 | 意味 |
| --- | --- | --- |
| `\d` | `[0-9]` | 数字1文字 |
| `\D` | `[^0-9]` | 数字以外の1文字 |
| `\w` | `[a-zA-Z0-9_]` | 任意の英数字とアンダーバー1文字 |
| `\W` | `[^a-zA-Z0-9_]` | 任意の英数字とアンダーバー以外の1文字 |
| `\s` | `[ \t\n\r\f\v]` | スペースや改行などの空白文字1文字 |
| `\S` | `[^ \t\n\r\f\v]` | 空白文字以外の1文字 |

<pre><code class="caution">\d や \w が、どこまでの文字にマッチするかは、言語によって違う。
Python 3 や Rust は、既定で Unicode に対応しており、\d が全角の数字に、\w が日本語の文字にも、マッチする。JavaScript や Java、Go では、ASCII の文字だけにマッチする。
確実に、半角の数字だけにしたい場合は、[0-9] と書く。</code></pre>

### 日本語の文字

日本語の文字は、Unicode の範囲で指定できる。

| 表現 | 対象 |
| --- | --- |
| `[ぁ-ん]` | ひらがな (長音符「ー」は、含まない) |
| `[ァ-ヶー]` | 全角のカタカナと、長音符 |
| `[一-龥]` | 常用的な漢字 (すべての漢字は、含まない) |
| `[０-９]` | 全角の数字 |
| `\p{Hiragana}` `\p{Katakana}` `\p{Han}` | Unicode のスクリプトで指定する (JavaScript は `u` フラグが必要。対応していない言語もある) |

## 量指定子 (繰り返し) <a id="quantifier" data-name="量指定子"></a>

直前の1つの要素を、何回繰り返すかを指定する。

| 表現 | 意味 | 例 | 一致する例 |
| --- | --- | --- | --- |
| `*` | 0回以上 | `ab*c` | `ac`、`abc`、`abbbc` |
| `+` | 1回以上 | `ab+c` | `abc`、`abbbc` (`ac` には、一致しない) |
| `?` | 0か1 | `colou?r` | `color`、`colour` |
| `{n}` | n回 | `\d{4}` | `2025` |
| `{n,}` | n回以上 | `\d{2,}` | `12`、`12345` |
| `{n,m}` | n回以上m回以下 | `\d{2,4}` | `12`、`123`、`1234` |

<pre><code class="tips">量指定子は、直前の「1つの要素」にだけ、かかる。
複数の文字を、まとめて繰り返したいときは、グループで囲む。ab+ は「a と、1回以上の b」、(ab)+ は「ab の、1回以上の繰り返し」。</code></pre>

### 貪欲 (最長一致) と非貪欲 (最短一致)

量指定子は、既定では、**できるだけ長く**一致する (貪欲)。後ろに `?` を付けると、**できるだけ短く**一致する (非貪欲)。

| 表現 | 意味 |
| --- | --- |
| `.*` | 貪欲。0文字以上を、最大まで |
| `.+` | 貪欲。1文字以上を、最大まで |
| `.*?` | 非貪欲。0文字以上を、最小まで |
| `.+?` | 非貪欲。1文字以上を、最小まで (最小1文字) |
| `??`、`{n,m}?` | `?` や `{n,m}` の、非貪欲版 |

```regex
<.*>
```

```html
<div>abc</div>
```

```text
<div>abc</div>   ← 貪欲: 最初の < から、最後の > まで
```

```regex
<.*?>
```

```text
<div>   ← 非貪欲: 最初の > で止まる
```

<pre><code class="tips">非貪欲の代わりに、「終わりの文字を含まない文字クラス」を使う方法もある。&lt;[^&gt;]*&gt; は、&gt; を含まない文字だけを、繰り返す。
非貪欲より、意図が明確で、処理も速いことが多い。</code></pre>

## 位置指定 (アンカー) <a id="anchor" data-name="位置指定"></a>

文字そのものではなく、**位置**に一致する。

| 表現 | 意味 |
| --- | --- |
| `^` | 先頭 (複数行モードでは、行頭) |
| `$` | 末尾 (複数行モードでは、行末) |
| `\b` | 単語境界 |
| `\B` | 単語境界以外 |
| `\A` | 文字列全体の先頭 (言語による) |
| `\z` | 文字列全体の末尾 (言語による。Python では `\Z`) |

```regex
^Hello
```

```text
Hello World   ← 一致 (先頭が Hello)
Say Hello     ← 一致しない
```

```regex
World$
```

```text
Hello World   ← 一致 (末尾が World)
World Cup     ← 一致しない
```

### ^ と $ の範囲

既定では、`^` と `$` は、**文字列全体の先頭と末尾**。複数行の文字列で、各行の先頭と末尾に一致させるには、複数行モード (フラグ `m`) にする。

| モード | `^` | `$` |
| --- | --- | --- |
| 既定 | 文字列の先頭 | 文字列の末尾 |
| 複数行 (`m`) | 各行の先頭 | 各行の末尾 |

<pre><code class="caution">検証 (バリデーション) では、^ と $ で、必ず前後を挟む。
挟まないと、部分一致 (文字列のどこかに、一致するだけ) になってしまう。たとえば、\d+ は、「abc123」にも一致する。</code></pre>

### 単語境界

`\b` は、「単語を構成する文字 (`\w`) と、それ以外の文字の、間」に一致する。

```regex
\bcat\b
```

```text
a cat sat      ← 一致
category       ← 一致しない (cat の後ろが、単語の文字)
```

<pre><code class="caution">単語境界 (\b) が、日本語などの ASCII 以外の文字を、単語として扱うかは、言語による。
JavaScript と Go は、ASCII だけを単語の文字として扱う。Python 3 と Rust は、Unicode で判定する。Java は、バージョンや設定で、挙動が異なる。
日本語の文章の区切りには、\b は、あまり向かない。</code></pre>

## グループと選択 <a id="group" data-name="グループと選択"></a>

文字クラス `[ ]` が、1文字だったのに対して、グループ `( )` は、ひとかたまりの文字列として扱う。

グループ内で `|` (パイプ) を使うと、「または」という意味になる。

| 表現 | 意味 |
| --- | --- |
| <code>(apple&#124;windows)</code> | apple か windows |
| <code>gr(a&#124;e)y</code> | gray か grey |
| `(ab)+` | ab の、1回以上の繰り返し |

### 選択 (|) の範囲

`|` は、**グループの中なら、グループ全体、グループの外なら、式全体**を、左右に分ける。

```regex
^cat|dog$       ← 「^cat」または「dog$」 (意図とは違うことが多い)
^(cat|dog)$     ← 「cat」または「dog」だけの文字列
```

<pre><code class="caution">^cat|dog$ は、「先頭が cat」または「末尾が dog」という意味になる。
「cat か dog のどちらかだけ」にしたいときは、^(cat|dog)$ と、グループで囲む。</code></pre>

### キャプチャ

グループ化すると、自動的にキャプチャ (一致した文字列を、番号を付けて保存) されて、後から、1番目のグループ、2番目のグループのように、再利用できる。<br>
非キャプチャを指定すると、キャプチャされなくなる。「または」や、量指定子のためだけに、グループを使うときに使える (番号がずれず、処理も軽い)。

| 表現 | 意味 |
| --- | --- |
| `(abc)` | キャプチャグループ |
| `(?:abc)` | 非キャプチャグループ |
| `(?<name>abc)` | 名前付きキャプチャグループ (Python では `(?P<name>abc)`) |

```regex
(\d{4})-(\d{2})-(\d{2})
```

```text
2025-11-04
  1番目: 2025
  2番目: 11
  3番目: 04
```

キャプチャした内容は、置換のときに、`$1`、`$2` (言語によっては `\1`、`\2`) で、使える。

```text
置換前: 2025-11-04
パターン: (\d{4})-(\d{2})-(\d{2})
置換後: $3/$2/$1
結果: 04/11/2025
```

### キャプチャ参照 (後方参照)

同じパターンの中で、前にキャプチャした内容を、参照できる。

| 表現 | 意味 |
| --- | --- |
| `\1` | 1番目のキャプチャと、同じ文字列 |
| `\2` | 2番目のキャプチャと、同じ文字列 |
| `\k<name>` | 名前付きキャプチャと、同じ文字列 (Python では `(?P=name)`) |

```regex
(\w+)\s+\1
```

```text
hello hello   ← 一致 (同じ単語の繰り返し)
test test     ← 一致
hello world   ← 一致しない
```

参照は、言語による。Rust と Go の標準の正規表現は、後方参照に対応していない。

## 先読みと後読み <a id="lookaround" data-name="先読みと後読み"></a>

文字そのものは、消費せずに、**前後に何があるか**だけを、条件として確認する。一致する範囲には、含まれない。

| 種類 | 書き方 | 意味 |
| --- | --- | --- |
| 肯定先読み | `X(?=Y)` | X の直後に、Y が続く |
| 否定先読み | `X(?!Y)` | X の直後に、Y が続かない |
| 肯定後読み | `(?<=Y)X` | X の直前に、Y がある |
| 否定後読み | `(?<!Y)X` | X の直前に、Y がない |

### 肯定先読み

```regex
\d+(?=円)
```

```text
100円   ← 一致する部分は「100」 (「円」は、含まれない)
500円   ← 「500」
100     ← 一致しない (後ろに「円」がない)
```

### 肯定後読み

```regex
(?<=\$)\d+
```

```text
$100   ← 一致する部分は「100」 (「$」は、含まれない)
```

### 否定先読み・否定後読み

<pre><code class="caution">否定の先読みと後読みは、書き方に注意が必要。
\d+(?!円) は、「100円」に対して、「10」に一致してしまう (数字を1文字減らして、後ろが「円」でない位置を、探すため)。
同様に、(?&lt;!\$)\d+ は、「$100」に対して、「00」に一致してしまう。</code></pre>

数字の「途中」で、一致させないために、数字の文字クラスも、条件に含める。

```regex
\d+(?![\d円])
```

```text
100円   ← 一致しない (最後の数字の後ろが、「円」)
100個   ← 一致 (「100」)
```

```regex
(?<![\d$])\d+
```

```text
$100    ← 一致しない
100     ← 一致 (「100」)
```

あるいは、単語境界を使う方法もある。

```regex
\b\d+\b(?!円)
```

### 先読みの使い道: 複数の条件を、すべて満たす

先読みは、位置を進めないため、**同じ位置から、複数の条件を、かけられる**。パスワードの形式の確認などに使う。

```regex
^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$
```

| 部分 | 意味 |
| --- | --- |
| `^` | 先頭から |
| `(?=.*[a-z])` | どこかに、英小文字が含まれる |
| `(?=.*[A-Z])` | どこかに、英大文字が含まれる |
| `(?=.*\d)` | どこかに、数字が含まれる |
| `.{8,}$` | 8文字以上 |

### 先読み・後読みの対応状況

| 言語・ツール | 先読み | 後読み |
| --- | --- | --- |
| JavaScript | 対応 | 対応 (ES2018 以降) |
| Python | 対応 | 対応 (**固定長のみ**) |
| Java | 対応 | 対応 (長さの上限が必要) |
| PCRE (PHP など) | 対応 | 対応 (固定長) |
| Go、Rust (標準の crate) | **非対応** | **非対応** |
| `grep -E`、`sed -E` | **非対応** | **非対応** (`grep -P` は、PCRE で対応) |

## フラグ (修飾子) <a id="flag" data-name="フラグ"></a>

パターン全体の、動作を変える。

| フラグ | 意味 | 例 |
| --- | --- | --- |
| `i` | 大文字小文字を区別しない | `/hello/i` は `Hello` にも一致 |
| `m` | 複数行モード (`^` と `$` が、各行に一致する) | |
| `s` | `.` が、改行にも一致する | |
| `x` | 空白とコメントを無視する (読みやすく書ける) | |
| `g` | すべての一致を対象にする (JavaScript で、置換や検索のときに指定する) | |
| `u` | Unicode モード (JavaScript で、`\p{...}` などを使うときに必要) | |

書き方は、言語によって違う。

| 言語 | 書き方 |
| --- | --- |
| JavaScript | `/hello/i`、`new RegExp("hello", "i")` |
| Python | `re.compile(r"hello", re.I)`、パターンの先頭に `(?i)` |
| Java | `Pattern.compile("hello", Pattern.CASE_INSENSITIVE)`、`(?i)` |
| Rust / Go / PCRE | パターンの先頭に `(?i)` |

### 読みやすく書く (x フラグ)

複雑なパターンは、`x` フラグ (verbose モード) で、空白とコメントを付けて、書くと、読みやすい。

```regex
(?x)
^(\d{4})   # 年
-(\d{2})   # 月
-(\d{2})$  # 日
```

<pre><code class="tips">x フラグが有効なときは、パターンの中の、空白が無視される。空白そのものを、検索したいときは、\s や [ ] を使う。</code></pre>

## よく使われる正規表現 <a id="example" data-name="よく使われる正規表現"></a>

### 数値

| 意味 | 正規表現 | 補足 |
| --- | --- | --- |
| 数字のみ | `^\d+$` | |
| 符号付きの整数 | `^-?\d+$` | |
| 小数 | `^-?\d+(\.\d+)?$` | `.5` や `5.` には、一致しない |
| カンマ区切りの数 | `^\d{1,3}(,\d{3})*$` | `1,234,567` |

### 日付と時刻

| 意味 | 正規表現 | 補足 |
| --- | --- | --- |
| 日付 | `^\d{4}-\d{2}-\d{2}$` | 形式だけを確認する (13月や32日も、一致する) |
| 日付 (月日の範囲つき) | <code>^\d{4}-(0[1-9]&#124;1[0-2])-(0[1-9]&#124;[12]\d&#124;3[01])$</code> | 月は1〜12、日は1〜31。月ごとの日数や、うるう年は確認できない |
| 時刻 (24時間) | <code>^([01]\d&#124;2[0-3]):[0-5]\d$</code> | `00:00`〜`23:59` |

<pre><code class="tips">日付の正しさ (存在する日付か) は、正規表現ではなく、日付を扱うライブラリで確認する。
正規表現は、形式の確認までにとどめるのが、現実的。</code></pre>

### 電話番号・郵便番号

| 意味 | 正規表現 | 補足 |
| --- | --- | --- |
| 電話番号 | `\d{2,4}-\d{2,4}-\d{4}` | 国内の固定電話の形式。前後を `^` と `$` で挟むと、全体の検証になる |
| 携帯電話 | `^0[789]0-\d{4}-\d{4}$` | `090`、`080`、`070` で始まる11桁 |
| 郵便番号 | `^\d{3}-\d{4}$` | ハイフンつき |

### 文字の種類

| 意味 | 正規表現 | 補足 |
| --- | --- | --- |
| ひらがなのみ | `^[ぁ-ん]+$` | 長音符「ー」は、含まない。必要なら `[ぁ-んー]` |
| 全角カタカナのみ | `^[ァ-ヶー]+$` | |
| 英数字のみ | `^[a-zA-Z0-9]+$` | |
| 半角英数字と記号 | `^[\x21-\x7E]+$` | ASCII の、印字できる文字 |
| 空白のみ (空も含む) | `^\s*$` | 空行や、空白だけの行の判定 |

### 文字列の形式

| 意味 | 正規表現 | 補足 |
| --- | --- | --- |
| ファイル拡張子 | <code>\.(txt&#124;png&#124;jpg)$</code> | 末尾が、`.txt`、`.png`、`.jpg` のいずれか |
| 特定のドメインのメールアドレス | <code>([a-zA-Z0-9._-]+)@(?:gmail\.com&#124;yahoo\.co\.jp)</code> | `gmail.com` か `yahoo.co.jp` のアドレスだけ |
| メールアドレス (簡易) | `^[\w.-]+@[\w.-]+\.[A-Za-z]{2,}$` | 簡易的な確認 (厳密には、できない) |
| URL (簡易) | `^https?://\S+$` | |
| IPv4 アドレス (簡易) | `^(\d{1,3}\.){3}\d{1,3}$` | 各数値が 0〜255 かは、確認しない |
| 16進数のカラーコード | `^#?[0-9a-fA-F]{6}$` | `#ff0000` |

<pre><code class="caution">メールアドレスや URL を、正規表現で、厳密に検証することは、非常に難しい (仕様が複雑で、完全に表現できない)。
上の例は、「明らかに違う形式」を弾くための、簡易的なもの。最終的な確認は、メールを送って確かめる、URL を専用のパーサーで解析する、といった方法を使う。</code></pre>

### 検索・置換でよく使う

| 目的 | 検索 | 置換後 | 補足 |
| --- | --- | --- | --- |
| 連続する空白を、1つにする | `\s{2,}` | (空白1つ) | |
| 行頭と行末の空白を、取り除く | <code>^\s+&#124;\s+$</code> | (空) | 行ごとに処理するなら、複数行モード (`m`) |
| 空行を、取り除く | `^\s*\n` | (空) | 複数行モード (`m`) |
| 同じ単語の連続を、探す | `\b(\w+)\s+\1\b` | | 後方参照が必要 |
| 括弧の中身を取り出す | `\(([^)]*)\)` | | 1番目のキャプチャが、中身 |
| ダブルクォートの中身 | `"([^"]*)"` | | |
| HTML のタグを、取り除く | `<[^>]+>` | (空) | 簡易的な方法。HTML の解析には、向かない |
| 日付の形式を変える | `(\d{4})-(\d{2})-(\d{2})` | `$3/$2/$1` | `\3/\2/\1` と書く言語もある |

## 言語ごとの違い <a id="dialect" data-name="言語ごとの違い"></a>

正規表現には、いくつかの方言がある。基本の構文は、ほとんど共通だが、高度な機能で違いが出る。

### 機能の対応

| 機能 | JavaScript | Python | Java | Go | Rust (標準の crate) | grep -E / sed -E |
| --- | --- | --- | --- | --- | --- | --- |
| 先読み | ○ | ○ | ○ | ✕ | ✕ | ✕ |
| 後読み | ○ | ○ (固定長) | ○ | ✕ | ✕ | ✕ |
| 後方参照 | ○ | ○ | ○ | ✕ | ✕ | ○ (拡張) |
| 名前付きグループ | `(?<n>)` | `(?P<n>)` | `(?<n>)` | `(?P<n>)` | `(?<n>)` | ✕ |
| `\d` `\w` の範囲 | ASCII | Unicode | ASCII | ASCII | Unicode | `\d` は、使えない (`[0-9]` を使う) |
| 実行時間の保証 | なし | なし | なし | 線形時間 | 線形時間 | 実装による |

<pre><code class="tips">Go と Rust の正規表現は、入力の長さに比例した時間で終わることを保証する代わりに、後方参照と先読みに対応していない。
これらが必要な場合は、パターンで取り出した後に、プログラムで判定するか、Rust なら fancy-regex などの別の crate を使う。</code></pre>

### 基本的な使い方

| 言語 | 一致の確認 | 置換 |
| --- | --- | --- |
| JavaScript | `/\d+/.test(s)` | `s.replace(/\d+/g, "N")` |
| Python | `re.search(r"\d+", s)` | `re.sub(r"\d+", "N", s)` |
| Java | `Pattern.compile("\\d+").matcher(s).find()` | `s.replaceAll("\\d+", "N")` |
| Go | ``regexp.MustCompile(`\d+`).MatchString(s)`` | `re.ReplaceAllString(s, "N")` |
| Rust | `Regex::new(r"\d+")?.is_match(s)` | `re.replace_all(s, "N")` |
| grep / sed | `grep -E '[0-9]+' file` | `sed -E 's/[0-9]+/N/g' file` |

### 置換での、キャプチャの参照

| 言語 | 1番目のグループ | 名前付きグループ |
| --- | --- | --- |
| JavaScript | `$1` | `$<name>` |
| Python | `\1` | `\g<name>` |
| Java | `$1` | `${name}` |
| Go / Rust | `$1`、`${1}` | `${name}` |
| sed | `\1` | (なし) |

<pre><code class="caution">正規表現を、文字列として書く言語 (Java、Python の通常の文字列など) では、バックスラッシュを、2回書く必要がある ("\\d+")。
Python の raw 文字列 (r"\d+")、Rust の raw 文字列 (r"\d+")、Go のバッククォート文字列 (`\d+`) を使うと、そのまま書ける。</code></pre>

### ^ と $ の細かな違い

| 言語 | 既定の `$` |
| --- | --- |
| JavaScript、Go、Rust | 文字列の、真の末尾だけに一致する |
| Python、Java、PCRE | 末尾と、**末尾の改行の直前**にも一致する |

末尾の改行があるかもしれない入力を、厳密に検証するときは、`\z` (Python は `\Z`) を使うと、確実。

### grep と sed の記法

| 種類 | 説明 |
| --- | --- |
| 基本正規表現 (BRE) | `grep` や `sed` の既定。`+`、`?`、<code>&#124;</code>、`(`、`)`、`{`、`}` を、特殊な意味にするには、`\+`、`\?` のように、エスケープが必要 |
| 拡張正規表現 (ERE) | `grep -E`、`sed -E`。この文書の書き方と、ほぼ同じ |
| Perl 互換 (PCRE) | `grep -P`。`\d` や先読みなどが、使える (GNU grep のみ) |

## 正規表現の組み立て方 <a id="build" data-name="正規表現の組み立て方"></a>

複雑な正規表現も、小さな部品を、1つずつ組み合わせて作る。

### 手順

| 手順 | 内容 |
| --- | --- |
| 1 | 一致させたい例と、一致させたくない例を、いくつか集める |
| 2 | 例の共通点を探して、文字クラスで、文字の種類を書く |
| 3 | 量指定子で、繰り返しを書く |
| 4 | 必要なら、`^`、`$`、`\b` で、位置を決める |
| 5 | 取り出したい部分を、`( )` で囲む |
| 6 | すべての例で、結果を確認する (特に、一致させたくない例) |

### 例: 日時を取り出す

```text
一致させたい: 2025-11-04 12:30
              2024-01-09 08:05
一致させたくない: 2025/11/04 12:30
                  25-11-04 12:30
```

| 段階 | 正規表現 |
| --- | --- |
| 日付の部分 (4桁-2桁-2桁) | `\d{4}-\d{2}-\d{2}` |
| 時刻の部分 (2桁:2桁) | `\d{2}:\d{2}` |
| 日付と時刻を、空白でつなぐ | `\d{4}-\d{2}-\d{2} \d{2}:\d{2}` |
| 各部分を、取り出せるようにする | `(\d{4})-(\d{2})-(\d{2}) (\d{2}):(\d{2})` |
| 前後を、固定する | `^(\d{4})-(\d{2})-(\d{2}) (\d{2}):(\d{2})$` |

<pre><code class="tips">長くなったパターンは、一度に書かずに、短い部分から、順に伸ばして、そのたびに確認する。
複雑になりすぎたら、正規表現1つで済ませず、複数の簡単な処理に、分けることも検討する。</code></pre>

## 性能 (バックトラック) <a id="performance" data-name="性能"></a>

多くの言語の正規表現エンジンは、「バックトラック」という方法で、一致を探す。条件が合わないと、前の選択に戻って、別の選択肢を試す。パターンによっては、この試行回数が、**入力の長さに対して、指数的に増える**ことがある。

```regex
^(a+)+$
```

```text
aaaaaaaaaaaaaaaaaaaaaaaaaaaa!   ← 最後に「!」があって、一致しない
                                   → 一致しないと分かるまでに、膨大な組み合わせを試す
```

| パターンの特徴 | 例 | 対処 |
| --- | --- | --- |
| 繰り返しの中に、繰り返し | `(a+)+`、`(.*)*` | 入れ子の繰り返しを避ける |
| 繰り返しの中の「または」が、重なる | <code>(a&#124;aa)+</code> | 選択肢が、重ならないようにする |
| 先頭の `.*` が、繰り返される | `.*foo.*bar.*` | 具体的な文字クラスにする |

これを悪用した攻撃を、ReDoS (Regular expression Denial of Service) と呼ぶ。

<pre><code class="caution">ユーザーが入力した値に、正規表現を適用するサーバーのコードでは、ReDoS に注意する。
入力の長さを制限する、タイムアウトを設ける、線形時間を保証するエンジン (Go の regexp、Rust の regex など) を使う、といった対策がある。</code></pre>

## よくある間違い <a id="pitfalls" data-name="よくある間違い"></a>

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| `.` が、改行に一致しない | `.` は、改行以外の文字 | `s` フラグを付ける。または `[\s\S]` と書く |
| 検証が、部分一致で通ってしまう | `^` と `$` がない | 前後を、`^` と `$` で挟む |
| `.txt` が、「atxt」にも一致する | `.` が、任意の1文字 | `\.txt` とエスケープする |
| `[]` の中で、意図しない動作 | `[ ]` の中では、特殊文字の意味が変わる (`^` や `-`) | `[ ]` の中の、特殊文字の扱いを確認する |
| `\` のエスケープ忘れ | 文字列リテラルでは、`\\` が必要な言語がある | raw 文字列を使う |
| `*` と `+` の混同 | `*` は 0回以上、`+` は 1回以上 | 「0回でもよいか」を、考えて選ぶ |
| 取りすぎる | 貪欲マッチ | 非貪欲 (`*?`) にする。または終わりの文字を除く (`[^>]*`) |
| <code>^cat&#124;dog$</code> が、意図と違う | <code>&#124;</code> の範囲が、式全体 | <code>^(cat&#124;dog)$</code> と、グループで囲む |
| `\d` が、全角の数字にも一致する | Unicode に対応した言語 (Python 3、Rust) | `[0-9]` と書く |
| 後読みで、エラーになる | 言語が、対応していない、または固定長でない | 言語ごとの対応を確認する。パターンを分けて、プログラムで判定する |
| 否定先読みが、意図どおりに動かない | 数字の途中の位置に、一致してしまう | `\d+(?![\d円])` のように、文字クラスも条件に含める |
| 入力によって、極端に遅くなる | バックトラック | 入れ子の繰り返しを避ける。線形時間のエンジンを使う |
| 言語を変えたら、動かない | 方言の違い | 「言語ごとの違い」を確認する |

## 覚え方 <a id="mnemonic" data-name="覚え方"></a>

| 記号 | 覚え方 |
| --- | --- |
| `\d` | digit (数字) |
| `\w` | word (単語の文字) |
| `\s` | space (空白) |
| `\b` | boundary (境界) |
| `^` | 始まり |
| `$` | 終わり |
| `+` | 1個以上 |
| `*` | 0個以上 |
| `?` | あってもなくてもよい |
| `.` | なんでも1文字 |
| `\D` `\W` `\S` | 大文字は、小文字の「否定」 |
| `(?=` `(?!` | 先読み (これから先を見る)。`=` は肯定、`!` は否定 |
| `(?<=` `(?<!` | 後読み (これまでを見る)。`<` が、後ろ向きの印 |
