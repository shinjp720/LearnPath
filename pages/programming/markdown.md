# Markdown <a id="top" data-name="TOP"></a>

Markdown は、プレーンテキストで、見出しや強調、リスト、リンクなどを書くための、軽量なマークアップ言語。書いたテキストは、HTML に変換されて表示される。

記号の書き方が直感的で、README、技術ノート、ブログ、チャットなど、さまざまな場所で使われている。ただし、Markdown には、処理系ごとの方言があり、同じ書き方が、すべての環境で動くとは限らない。

---

## 概要 <a id="overview" data-name="概要"></a>

### 特徴

| 特徴 | 内容 |
| --- | --- |
| プレーンテキスト | 特別なエディタがなくても、読み書きできる |
| HTML に変換 | 見出しは `<h1>`、リストは `<ul>` のように、対応する HTML になる |
| HTML を混ぜられる | Markdown で書けない表現は、HTML をそのまま書ける |
| 方言がある | 処理系によって、使える記法が違う |

### 処理系による違い

| 処理系 | 内容 |
| --- | --- |
| CommonMark | Markdown の仕様を、厳密に定めたもの。基本の記法だけを持つ |
| GFM (GitHub Flavored Markdown) | CommonMark に、テーブル、取り消し線、チェックリスト、自動リンクを足したもの |
| kramdown | Ruby 製の処理系。Jekyll の既定。脚注、定義リスト、`{#id}` などの独自記法を持つ |

### 記法ごとの対応

| 記法 | CommonMark | GFM | kramdown |
| --- | --- | --- | --- |
| 見出し、強調、リスト、引用、コード、リンク、画像 | ○ | ○ | ○ |
| テーブル | ✕ | ○ | ○ |
| 取り消し線 (`~~`) | ✕ | ○ | ✕ |
| チェックリスト | ✕ | ○ | ✕ |
| 裸の URL の自動リンク | ✕ | ○ | ✕ |
| 脚注 | ✕ | ○ (GitHub 上) | ○ |
| 定義リスト | ✕ | ✕ | ○ |
| アラート (`> [!NOTE]`) | ✕ | ○ (GitHub 上) | ✕ |

○ は、標準で使えるもの。✕ は、標準では使えないもの。使えない記法は、HTML で代用する。

### ブロック要素とインライン要素

Markdown の要素は、2種類に分けられる。

| 種類 | 内容 | 要素 |
| --- | --- | --- |
| ブロック要素 | 段落のように、行のまとまりを作る。前後を、空行で区切る | 見出し、リスト、引用、コードブロック、水平線、テーブル |
| インライン要素 | 文章の途中に、埋め込む | 強調、インラインコード、リンク、画像 |

<pre><code class="caution">この表の、処理系ごとの対応は、GFM と kramdown を基準にしている。実際に使っているサイトの処理系と設定は、サイトの設定ファイルで確認する。
特に、取り消し線とチェックリストは、kramdown の標準では使えず、そのまま表示されることがある。</code></pre>

## マークダウン (Markdown) の要素一覧 <a id="elements" data-name="要素一覧"></a>

### 見出し (Headings) <a id="headings" data-name="見出し"></a>

種類: ブロック要素。

```markdown
# 見出し1
## 見出し2
### 見出し3
#### 見出し4
##### 見出し5
###### 見出し6
```

`#` の数が、見出しの階層になる。

<pre><code class="caution"># と見出しの文字の間には、半角スペースが必要になる。#見出し と書くと、見出しにならない処理系が多い。
見出しの直前の行が、空行でないと、見出しとして解釈されない場合がある。</code></pre>

下線の形で書く記法もある (Setext 形式)。1と2の、2段階だけを書ける。

````markdown
見出し1
=======

見出し2
-------
````

<pre><code class="tips">ドキュメントの H1 は、1つだけにする。見出しの階層は、飛ばさない (## の次に #### を置かない)。</code></pre>

### 強調 (Emphasis) <a id="emphasis" data-name="強調"></a>

種類: インライン要素。

```markdown
*斜体* または _斜体_
**太字** または __太字__
***斜体+太字*** または ___斜体+太字___
~~取り消し線~~
```

| 表示 | 書き方 | 変換される HTML |
| --- | --- | --- |
| 斜体 | `*斜体*` | `<em>` |
| 太字 | `**太字**` | `<strong>` |
| 斜体と太字 | `***両方***` | `<em><strong>` |
| 取り消し線 | `~~取り消し~~` | `<del>` (GFM のみ) |

<pre><code class="caution">~~ の取り消し線は、GFM の拡張で、kramdown の標準では使えない。使えない環境では、HTML の s タグ (&lt;s&gt;取り消し&lt;/s&gt;) を使う。
日本語の文章では、** の前後に、全角の記号や括弧があると、太字として認識されないことがある。その場合は、前後に半角スペースを入れる。</code></pre>

### リスト (Lists) <a id="lists" data-name="リスト"></a>

#### 番号なしリスト (Unordered List)

種類: ブロック要素。

```markdown
- アイテム1
    - サブアイテム
        - さらにサブアイテム
* 別の記法
+ 別の記法
```

`-`、`*`、`+` の、どれでも書ける。入れ子は、インデントで表す。

<pre><code class="tips">記号は、ドキュメント内で、1種類に統一する (このノートでは -)。記号を変えると、別のリストとして扱われる処理系がある。
インデントは、2〜4 スペースで、そろえる。タブは、避ける。</code></pre>

#### 番号付きリスト (Ordered List)

種類: ブロック要素。

```markdown
1. アイテム1
2. アイテム2
    1. サブアイテム
    2. サブアイテム
3. アイテム3
```

<pre><code class="tips">表示される番号は、最初の番号から、連番になる。書く番号が、すべて 1. でも、連番として表示される処理系が多い。項目の順序を、あとから入れ替えやすくなる。</code></pre>

#### リストの中の段落とコード

項目の中に、段落やコードブロックを入れるときは、空行を置いて、項目の内容の位置まで、インデントする。

````markdown
1. 手順1

    説明の段落。

    ```bash
    echo "リストの中のコード"
    ```

2. 手順2
````

### 引用 (Blockquote) <a id="blockquote" data-name="引用"></a>

種類: ブロック要素。

```markdown
> これは引用です。
>> ネストされた引用
>>> さらにネスト
```

引用の中には、リストやコードなど、ほかの記法も書ける。

```markdown
> 引用の段落。
>
> - 引用の中のリスト
> - もう1つの項目
```

### コード (Code) <a id="code" data-name="コード"></a>

#### インラインコード

種類: インライン要素。

```markdown
`print("Hello, World!")`
```

コードの中に、バッククォートを含めるときは、外側を、二重のバッククォートで囲む。

````markdown
``コードの中の `バッククォート` ``
````

#### コードブロック

種類: ブロック要素。

````markdown
```
print("Hello, World!")
```
````

または言語指定:

````markdown
```python
def hello():
    print("Hello, World!")
```
````

言語を指定すると、構文が色分けされる。

| 内容 | 指定 |
| --- | --- |
| シェルコマンド | `bash` |
| 出力の例、図、ツリー | `text` |
| Markdown のサンプル | `markdown` |
| HTML、CSS、SQL | `html`、`css`、`sql` |

<pre><code class="tips">コードブロックの中に、バッククォート3つのコードブロックを書くときは、外側を、バッククォート4つにする。このノートの例も、その書き方になっている。
バッククォートの代わりに、チルダ3つ (~~~) で囲む書き方もある。</code></pre>

### リンク (Links) <a id="links" data-name="リンク"></a>

種類: インライン要素。

```markdown
[リンクテキスト](https://example.com)
[リンクテキスト](https://example.com "タイトル")
```

```markdown
<https://example.com>
```

`<` と `>` で URL を囲むと、URL そのものが、リンクになる。

URL を、文章の外に、まとめて書く書き方もある (参照形式)。同じ URL を、何度も使うときに、読みやすくなる。

```markdown
[リンクテキスト][ref]

[ref]: https://example.com "タイトル"
```

#### 任意の位置へのリンク

マークダウンを用いて、任意の位置へのリンクを貼る場合は、<br>
要素に id を持たせて、`[テキスト](#id)` とする。

```markdown
<p id="here">ジャンプ先</p>

[ジャンプ先へジャンプ](#here)
```

もしくは、`[テキスト](#見出し)` とする。<br>
日本語も可能だが、空白は -(ハイフン)に、英大文字は英小文字にする必要がある。<br>
また記号は無視される。

```markdown
### ジャンプ先

[ジャンプ先へジャンプ](#ジャンプ先)
```

| 見出し | リンクの書き方 |
| --- | --- |
| `### Hello World!` | `[テキスト](#hello-world)` |
| `### ジャンプ先` | `[テキスト](#ジャンプ先)` |

<pre><code class="caution">見出しから自動で作られる ID は、処理系によって違う。kramdown の標準では、見出しの ID に、ASCII の文字だけが使われるため、日本語の見出しには、期待した ID が付かない。
GitHub 上では、日本語の見出しにも、ID が付く。確実にリンクするには、a タグの id で、ID を明示する。</code></pre>

```markdown
### ジャンプ先 <a id="jump" data-name="ジャンプ先"></a>

<a href="#jump">ジャンプ先へジャンプ</a>
```

<pre><code class="tips">ページへのリンクを貼る場合は
[C言語|プリプロセッサ](pages/c/c#preprocessor)
のように書く</code></pre>

### 水平線 (Horizontal Rule) <a id="horizontal-rule" data-name="水平線"></a>

種類: ブロック要素。

```markdown
---
***
___
```

| 書き方 | 内容 |
| --- | --- |
| `---` | ハイフン3つ以上 |
| `***` | アスタリスク3つ以上 |
| `___` | アンダースコア3つ以上 |

<pre><code class="caution">文章の直後の行に、--- を書くと、水平線ではなく、直前の行が、見出し (Setext 形式) になる。水平線の前には、空行を置く。</code></pre>

### 画像 (Images) <a id="images" data-name="画像"></a>

種類: インライン要素。

```markdown
![代替テキスト](https://example.com/image.jpg)
![代替テキスト](https://example.com/image.jpg "タイトル")
```

リンクの先頭に `!` を付けた形になる。画像に、リンクを付けるときは、画像の記法を、リンクで囲む。

```markdown
[![代替テキスト](https://example.com/image.jpg)](https://example.com)
```

Markdown では、画像の大きさを指定できない。大きさを指定するときは、HTML を使う (HTML のドキュメントを参照)。

```html
<img src="https://example.com/image.jpg" alt="代替テキスト" width="300">
```

<pre><code class="tips">代替テキストは、画像が表示されないときや、読み上げのときに使われる。画像の内容が分かる文を書く。</code></pre>

### テーブル (Tables) <a id="table" data-name="テーブル"></a>

種類: ブロック要素。<br>
ハイフンは 3つ以上でよい。

```markdown
| 見出し1 | 見出し2 | 見出し3 |
| ------- | ------- | ------- |
| 内容1   | 内容2   | 内容3   |
| 内容A   | 内容B   | 内容C   |
```

または整列を指定:

```markdown
| 左寄せ | 中央寄せ | 右寄せ |
| :----- | :------: | -----: |
| 左     |   中央   |     右 |
| A      |    B     |      C |
```

| 区切り行の書き方 | 整列 |
| --- | --- |
| `:---` | 左寄せ |
| `:---:` | 中央寄せ |
| `---:` | 右寄せ |

| 問題 | 回避策 |
| --- | --- |
| ヘッダー行と区切り行がない | 表として認識されない。2行目の区切り行は、必須 |
| セルの中に <code>&#124;</code> を書きたい | 表が崩れる。`&#124;` と書く。コードの中では、`<code>a&#124;b</code>` と書く |
| セルの中で、改行したい | `<br>` を使う |
| 列の数が、行によって違う | 全行で、同じ数にする |

<pre><code class="tips">列の幅は、揃えなくてよい。区切り行を、| --- | --- | の簡易形にしても、表になる。</code></pre>

### チェックリスト (Task List) <a id="task-list" data-name="チェックリスト"></a>

```markdown
- [ ] 未完了のタスク
- [x] 完了したタスク
```

`[ ]` の中の、スペースが空のものが未完了で、`x` が入るものが、完了になる。

<pre><code class="caution">チェックリストは、GFM の拡張である。kramdown の標準では、チェックボックスにならず、[ ] の文字が、そのまま表示される。</code></pre>

### HTMLの埋め込み <a id="html" data-name="HTMLの埋め込み"></a>

```markdown
<div style="color: red;">赤いテキスト</div>
```

Markdown の中には、HTML を、そのまま書ける。Markdown で書けない表現 (色、画像の大きさ、折りたたみなど) に使う。HTML の詳細は、HTML のドキュメントを参照。

| 種類 | 例 | 内容 |
| --- | --- | --- |
| ブロックの HTML | `<div>`、`<table>`、`<details>` | 前後を、空行で区切る |
| インラインの HTML | `<br>`、`<s>`、`<kbd>` | 文章の途中に、書ける |

kramdown では、ブロックの HTML の中は、そのままでは、Markdown として変換されない。`markdown="1"` の属性を付けると、中身が、Markdown として変換される。

```markdown
<div markdown="1">
**この中も、Markdown として変換される。**
</div>
```

<pre><code class="caution">GitHub では、安全のため、script や iframe などの一部のタグが、無効になる (GFM の、許可されない生の HTML)。
HTML の中に、&lt; や &amp; をそのまま表示したいときは、&amp;lt; や &amp;amp; のように、エスケープする。</code></pre>

### エスケープ (特殊文字) <a id="escape" data-name="エスケープ"></a>

```markdown
\*これでアスタリスクをエスケープ\*
```

記号の前に、バックスラッシュ (`\`) を付けると、その記号が、そのまま表示される。エスケープできる主な記号は、次のとおりである。

```text
\ ` * _ { } [ ] ( ) # + - . ! |
```

<pre><code class="tips">コードブロックと、インラインコードの中は、エスケープしなくても、記号がそのまま表示される。</code></pre>

### 改行 <a id="br" data-name="改行"></a>

意図的に改行を入れたい場合は、**行末にスペースを2つ**、または**&lt;br&gt;**タグを入れる。

| 書き方 | 内容 |
| --- | --- |
| 行末にスペース2つ | その行で改行する。スペースが、見えにくい |
| `<br>` | その位置で改行する。確実で、見て分かる |
| 空行 | 段落を分ける。段落の間に、余白ができる |

<pre><code class="tips">ソースの上で、単に改行しただけでは、HTML では、改行にならず、半角スペースになる処理系が多い。
kramdown には、日本語などの文字の間の改行を、取り除く設定がある。設定は、サイトの設定ファイルで確認する。</code></pre>

### 定義リスト (対応エンジンが必要) <a id="def-list" data-name="定義リスト"></a>

```markdown
用語1
: 定義1

用語2
: 定義2
```

kramdown では使えるが、CommonMark と GFM では、使えない。使えない環境では、HTML の `<dl>`、`<dt>`、`<dd>` で書く。

```html
<dl>
  <dt>用語1</dt>
  <dd>定義1</dd>
</dl>
```

## 拡張記法 <a id="extensions" data-name="拡張記法"></a>

処理系ごとの拡張。使えるかどうかは、環境によって違う。

### 脚注 <a id="footnote" data-name="脚注"></a>

```markdown
本文に、脚注を付ける[^1]。

[^1]: 脚注の内容。ページの下に、まとめて表示される。
```

GitHub と、kramdown で使える。CommonMark では、使えない。

### アラート <a id="alert" data-name="アラート"></a>

```markdown
> [!NOTE]
> 読み飛ばしても、知っておきたい情報。
```

| 種類 | 用途 |
| --- | --- |
| `[!NOTE]` | 補足の情報 |
| `[!TIP]` | 役に立つ助言 |
| `[!IMPORTANT]` | 重要な情報 |
| `[!WARNING]` | 注意が必要な内容 |
| `[!CAUTION]` | 危険が伴う内容 |

<pre><code class="caution">アラートは、GitHub の拡張で、ほかの処理系では、ただの引用として表示される。このサイトでは、補足や注意に、HTML の pre タグを使う (このサイトでの書き方を参照)。</code></pre>

### 折りたたみ <a id="details" data-name="折りたたみ"></a>

HTML の `<details>` で、クリックで開閉する部分を作れる。

```html
<details>
<summary>クリックで開く</summary>

開いたときに表示される内容。

</details>
```

<pre><code class="tips">中身を Markdown で書くときは、summary の後と、閉じタグの前に、空行を置く。kramdown では、details タグに、markdown="1" の属性が必要になる場合がある。</code></pre>

### 見出しへの ID の指定 (kramdown)

kramdown では、見出しの末尾に、`{#id}` と書いて、ID を指定できる。

```markdown
### 見出し {#my-id}
```

<pre><code class="tips">この書き方は、kramdown だけで動く。GitHub 上では、そのまま表示される。ほかの環境でも動く、a タグで ID を付ける書き方と、混ぜない。</code></pre>

## このサイトでの書き方 <a id="site" data-name="このサイトでの書き方"></a>

このサイトのドキュメント (Jekyll) で、使っている書き方。標準の Markdown に、サイト独自の HTML を、足している。

| 項目 | 規則 |
| --- | --- |
| front matter | 先頭に `title` と `layout: default` を書く |
| H1 | ファイルに1つだけ。`<a id="top" data-name="TOP"></a>` を付ける |
| `##` | `<a id="..." data-name="..."></a>` を付けて、前に `---` を置く |
| ページ内のリンク | Markdown の `[名前](#id)` ではなく、HTML の `<a href="#id">名前</a>` で書く |
| 補足と注意 | `<pre><code class="tips">`、`<pre><code class="caution">` |
| 短い例 | `<pre><code class="example">` (新規には、コードブロックを使う) |
| 取り消し線 | `~~` ではなく、`<s>取り消し</s>` |
| 強制改行 | 行末に `<br>` |

````markdown
---
title: 名前
layout: default
---

# 名前 <a id="top" data-name="TOP"></a>

導入の段落。

---

## 概要 <a id="overview" data-name="概要"></a>

<pre><code class="tips">補足の内容。</code></pre>

<pre><code class="caution">注意の内容。</code></pre>
````

<pre><code class="caution">補足と注意の pre タグの中は、プレーンテキストになる。Markdown の記法は、変換されない。&lt; は &amp;lt;、&gt; は &amp;gt;、&amp; は &amp;amp; と書く。</code></pre>

### Jekyll の Liquid

Jekyll は、コードブロックの中も含めて、ファイルのすべての場所で、波括弧2つで始まる記法 (<code>&#123;&#123;</code>) と、波括弧とパーセントで始まる記法 (<code>&#123;%</code>) を、Liquid として解釈する。説明のために書いた、これらの記号が、消えたり、エラーになったりする。

| 書き方 | 内容 |
| --- | --- |
| <code>&#123;% raw %&#125;</code> | これ以降を、Liquid として解釈しない |
| <code>&#123;% endraw %&#125;</code> | 解釈しない範囲の終わり |

この2つのタグで、該当する箇所を、前後から囲む。コードブロックの場合は、ブロックの前後の行に置く。

<pre><code class="tips">Vue のテンプレートや、GitHub Actions の YAML のように、波括弧2つを使う言語のコードは、特に注意する。波括弧が1つだけの記法 (JSON など) は、問題にならない。
raw のタグは、入れ子にできない。</code></pre>

## よくある落とし穴 <a id="pitfalls" data-name="よくある落とし穴"></a>

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| `#見出し` が、見出しにならない | `#` の後ろに、スペースがない | `# 見出し` のように、半角スペースを入れる |
| 水平線のつもりが、直前の行が見出しになった | 文章の直後に、`---` を書いている (Setext 形式) | 水平線の前に、空行を置く |
| 改行したのに、1行に、つながって表示される | 単純な改行は、改行として扱われない | 行末にスペース2つ。または、`<br>` を付ける |
| リストが、入れ子にならない | インデントが足りない。または、タブとスペースが、混ざっている | 2〜4 スペースで、そろえる |
| 番号付きリストの番号が、思った番号と違う | 最初の番号から、連番になる | 最初の番号だけを、意識する |
| 表が、崩れる | ヘッダー行や区切り行がない。または、セルにパイプ (<code>&#124;</code>) がある | 区切り行を書く。セルの中のパイプは、`&#124;` にする |
| 意図しない所が、強調になった | `*` や `_` が、記号として解釈された | `\*`、`\_` のように、エスケープする |
| コードブロックの中に、コードブロックが、書けない | 内側の ``` で、外側が、閉じてしまう | 外側を、バッククォート4つにする |
| 日本語の見出しへのリンクが、効かない | 見出しの ID が、処理系で違う (kramdown の標準は ASCII のみ) | a タグの `id` を明示して、`<a href="#id">` でリンクする |
| `~~取り消し線~~` や `- [ ]` が、そのまま表示される | kramdown の標準では、使えない記法 | `<s>` で書く。チェックリストは、使わない |
| HTML の中の Markdown が、変換されない | ブロックの HTML の中は、変換されない処理系がある | `markdown="1"` を付ける。または、Markdown で書き直す |
| <code>&#123;&#123;</code> や <code>&#123;%</code> の記述が、消える (Jekyll) | Liquid として解釈される | `raw` と `endraw` で囲む |
| 画像の大きさが、変えられない | Markdown の画像の記法に、大きさの指定がない | HTML の `<img>` に、`width` を指定する |
